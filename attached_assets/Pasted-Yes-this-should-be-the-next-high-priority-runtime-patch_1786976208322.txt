Yes—this should be the next high-priority runtime patch. It fixes the core category error: **data acquisition failure must never be presented as model judgment**.

One architectural correction: keep lifecycle state, data status, failure class, and terminal label separate. `INCOMPLETE_INPUT`, `DATA_PROVIDER_OUTAGE`, and `STALE_DATA` should be typed data statuses—not replacements for native WOW terminal labels.

## Four gates

1. **Identity/status gate**

   * Canonical player and event
   * Correct slate
   * Participant active
   * Lineup/starter status checked

2. **Role/opportunity gate**

   * Minutes, workload, lineup slot or projected role
   * Teammate/on-off context where applicable
   * Role certainty and timestamp

3. **Historical-ledger gate**

   * Raw L5 and L10 values
   * Exact-line hit rates, median and recent average
   * Role-valid sample
   * Whole-number push frequency

4. **Market/settlement gate**

   * Exact line and boundary
   * Push/DNP/void rules
   * Both market directions or an explicit unavailable status
   * Market probability, no-vig where applicable, timestamp and TTL

Only rows clearing all four may become `MODEL_READY`.
