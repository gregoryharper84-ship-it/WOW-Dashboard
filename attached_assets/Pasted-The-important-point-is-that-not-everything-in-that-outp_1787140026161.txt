## The 10 `SLATE_PURGE` rows need a different fix

Those are not model failures.

WOW's slate integrity rules correctly remove an event once it starts. Removing that gate would contaminate the forward test. The proper fix is **latency-aware scheduling**.

When you upload a screenshot at, say, 5:39 PM and some props start at 6:00 PM, WOW should immediately:

```text
UPLOAD
↓
extract every row
↓
freeze intake manifest
↓
resolve event start times
↓
sort by TIME_TO_START
↓
score imminent events first
↓
then perform broad cross-sport discovery
```

Today the workflow spent enough time doing other work that some initially valid rows crossed their start time.

So the permanent rule should be:

```text
user-supplied rows have priority over discovered rows
earliest event start has priority within supplied rows
```

That would materially improve the completeness patch without weakening slate integrity.
