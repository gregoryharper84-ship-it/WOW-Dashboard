Source hierarchy for the ledger build

1. Baseball Savant — controlling ledger source

For every pitcher:

filter:
pitcher = MLBAM pitcher ID
inning = 1
game_type = Regular Season
date range = 2026 season through board date

Group by:

game_pk
game_date
pitcher
inning

Then count actual pitch rows. The resulting per-game count becomes:

first_inning_pitches

Plate appearances can be grouped using at_bat_number or the pitch-event sequence to derive:

first_inning_batters_faced
P(BF=3)
P(BF=4)
P(BF>=5)

The CSV documentation confirms the dataset includes inning-level pitch records and the fields needed for pitch-location and event analysis. 

2. FanGraphs — role and start validation

FanGraphs game logs are useful for verifying:

* start date
* opponent
* starter designation
* innings pitched
* total batters faced
* strikeouts, walks and full-game workload

However, the standard game-log table does not provide first-inning pitch totals directly. 

3. Brooks Baseball — pitch-sequence cross-check

Brooks Baseball provides start-by-start pitch analysis by date, game and pitcher, making it useful for confirming individual pitch sequences when Savant contains an ambiguous or missing record.

Important distinction

Baseball Savant can produce the historical ledger, but it does not itself produce the WOW event-tree probability. Once these ledgers are assembled, they must still be submitted to the 1IP backend along with:

* confirmed top-four lineup
* catcher
* current health regime
* first-pitch strike and zone trends
* opponent P/PA profiles
* fourth-batter dependency inputs
* payout context

FanGraphs and Brooks Baseball therefore supplement the process; they do not replace Savant’s pitch-level ledger.
