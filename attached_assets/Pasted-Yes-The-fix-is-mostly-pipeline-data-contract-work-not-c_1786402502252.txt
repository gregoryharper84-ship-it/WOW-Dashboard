For H+R+RBI, reconstruct each game’s value from official H + R + RBI, then create the exact-line L5/L10/season ledger. For Hitter Fantasy Score, reconstruct each game’s score from the verified PrizePicks scoring definition plus official box-score components. Then run both MORE and LESS, apply the thin-market haircut, and keep the sportsbook comparison in a separate market-sanity lane. The exact market is needed for a verified market-edge/no-vig claim, but the active confidence/market separation architecture allows research confidence to survive when the exact comparison market is unavailable. We still need exact PrizePicks line, settlement identity, historical distribution, reconstruction, uncertainty, and calibration.     * box_score_log: dictionaries containing at least MIN, PTS, REB, AST, FGA, and a valid usage key such as USG%.
    Also supply role_status and a fresh ISO-8601 role_timestamp. Those two log fields cannot be interchanged. The contract says fewer than 3 qualifying non-DNP games triggers a role hold, while the caller guidance asks for at least 5 when possible. WNBA_Enrichment_Key_Contract_2026-08-03.docx

There is also a separate image-ingestion bug. The backend health check now advertises multipart_image_support=true, but the JIT /analyze-and-score adapter was sending a local /mnt/data/... path where the endpoint expected actual image bytes/base64 or a reachable URL. When I sent base64 manually, the vision service still rejected the image. The permanent fix is for the adapter to read the image bytes, normalize/recompress if needed, and send a valid MIME-bearing upload such as data:image/jpeg;base64,..., or use the backend’s multipart route directly. That failure is an integration problem, not a reason to reject the props.

One more thing I would fix: research rescans should not count as cross-slip exposure. We saw repeated analysis of the same Flau’jae row eventually produce a concentration blocker. With record_entries=false, scoring-only reruns should not behave like submitted/proposed tickets. Exposure should be written only when a card is actually registered as proposed/open/submitted. Otherwise repeated QA scans can poison the session ledger.

screenshot → normalize → auto-research → MLB proprietary reconstruction / WNBA enrichment → confidence model → market sanity separately → calibration → slip construction → exposure only on actual card registration.
