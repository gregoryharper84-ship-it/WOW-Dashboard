### 2. Excluded candidates should receive explicit terminal audit actions

In Tests 1 and 2, Embiid and Booker were silently excluded because only card sizes `[3, 2]` were built. That is structurally correct, but row reconciliation should explicitly show:

```text
action=EXCLUDED_CARD_SIZE_CEILING
detail=Candidate qualified individually but was not included because MAX_CARD_SIZE=3
```

Similarly, the weak 0.50 CLB leg should ideally change from the initial generic `INCLUDE` to:

```text
action=REMOVED_BY_WEAKEST_LEG_FINALIZER
```

This improves explainability without changing card behavior.

### 3. Do not automatically label every negative-return settlement as variance

Test 7 returned:

```text
process_label=PROCESS_PASS_VARIANCE_LOSS
```

That label is valid only when the stored entry-time record proves that every required process gate passed. A settlement request containing only entry and return values cannot by itself establish variance.

Safer logic:

```text
if documented_entry_time_process_pass:
    PROCESS_PASS_VARIANCE_LOSS
else:
    UNRESOLVED
```

or:

```text
PROCESS_FAIL_STRUCTURE
```

when the original card violated a now-active structure rule.

This follows the patch requirement that a loss cannot be called variance until all entry-time gates are documented.
