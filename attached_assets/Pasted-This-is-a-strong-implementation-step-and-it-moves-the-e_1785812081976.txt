## The main remaining limitation

The `PROVISIONAL` NBA/WNBA Poisson models are useful as an interim research layer, but they should not yet be treated as the final “best hit probability formulas.”

A game-log mean Poisson model assumes:

* the player’s opportunity is stable;
* variance is approximately equal to the mean;
* minutes are stable;
* role is unchanged;
* opponent context is negligible;
* teammate availability does not materially redistribute usage;
* game script has limited effect.

Those assumptions are often weak for basketball props.

The registry status correctly identifies this limitation, but the downstream label rules must enforce it. A `PROVISIONAL` model should have a ceiling such as:

```text
maximum_ceiling = MODEL_QUALIFIED_HOLD
power_eligibility = false
money_grade_allowed = false
calibration_status = PROVISIONAL
```

A high numeric result from the Poisson model must not override that ceiling.

    "push_probability": 0.0,
    "calibration_status": "PROVISIONAL",
    "probability_publishable": true,

  }

Calling a provisional adjusted value “calibrated” without a real calibration ledger could be misleading. When genuine cohort calibration is unavailable, the response should say so directly.

## Web fallback still needs a real execution contract

The response includes:

```text
web_fallback_used
sources
```

That is good, but the backend still needs a deterministic retry loop rather than merely reporting the gap.

The desired flow is:

```text
/analyze-and-score
→ identify missing required fields
→ return structured acquisition requests
→ GPT researches only those fields
→ GPT submits sourced enrichment
→ backend revalidates and rescoring occurs
```

A useful gap response would look like:

```json
{
  "data_gaps": [
    {
      "field": "box_score_log",
      "required_for": "WNBA opportunity gate",
      "preferred_sources": [
        "official league box scores",
        "official team game logs",
        "trusted structured provider"
      ],
      "minimum_records": 5,
      "accepted_format": "list[dict]",
      "resubmission_key": "enrichment.box_score_log"
    }
  ]
}
```

That gives the GPT precise instructions and prevents broad, uncontrolled research.

## The WNBA enrichment contract must be implemented server-side

The document created earlier should now become a validator in the backend, not just documentation.

The backend should reject or soft-hold based on type:

```text
game_log must be list[number]

```

It should also return an explicit contract error when the keys are mixed:

```text
WNBA_ENRICHMENT_TYPE_MISMATCH
```

That is preferable to allowing either module to silently filter or reject the data.

The opportunity engine should consume:

The L5/L10 module should consume only:
