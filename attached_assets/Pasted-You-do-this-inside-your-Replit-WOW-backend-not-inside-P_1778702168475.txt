You do this inside your Replit WOW backend, not inside PrizePicks and not inside ChatGPT.

Your Master memory/rules file already has the right philosophy: L5/L10 logs are part of the Data layer, projection is required for Final Approval, and missing data changes state instead of becoming approval.  ￼ The patch needs to go where the engine turns board props into scored candidates.

Main places to patch

1. Daily scan route/controller

Find the code that powers:

runWowDailyScan
DAILY_SPORTSBOOK_SCAN
CANDIDATE_DISCOVERY
PRE_LOCK_REFRESH
FINAL_LOCK

This is where you add:

"requested_sports": ["NBA", "MLB", "WNBA", "NHL"],
"scanned_sports": ["MLB", "WNBA", "NHL"],
"missing_sports": ["NBA"],
"scan_valid": false

Hard rule: if requested sport is missing, fail the scan.

Search Replit for:

runWowDailyScan
sports scanned
execution_report
l5_l10_called

2. L5/L10 service

Find the file/function that creates:

"l5_hit_rate"
"l10_hit_rate"
"l10_median"
"recent_avg"

This is the most important patch.

It should stop returning only summaries. It must return raw rows:

"raw_l5": [
  {
    "date": "2026-05-01",
    "opponent": "CLE",
    "stat": 36,
    "line": 39.5,
    "hit": true
  }
],
"raw_l10": [],
"games_available": 10,
"sample_scope": "current_season",
"cross_season_used": false,
"manual_fallback_used": false,
"log_status": "RAW_LOG_VERIFIED"

l5

3. Manual L10 fallback setting

Find where this parameter is handled:

"run_manual_l10_if_needed": true

For live slips, force it to:

"run_manual_l10_if_needed": false

Manual fallback can stay available only for research mode.

Rule:

environment=live + manual_fallback_used=true = block approval

What not to change

Do not change the whole WOW model.

The broken part is the pipeline:

board scan → sport ingestion → L5/L10 feature generation → approval gate

The model rules are already correct. The backend just needs to enforce them.
