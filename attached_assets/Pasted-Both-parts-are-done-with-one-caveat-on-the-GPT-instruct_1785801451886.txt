The real bug (not what the original diagnosis assumed): All three gate failures traced back to one root cause — the backend reads enrichment.game_log in two different modules that expect incompatible formats. l5_l10_ledger.py (the L5/L10 gate) needs game_log as a plain list of numbers. opportunity_engine.py (the WNBA role/opportunity gate) needs a list of per-game dicts. Both were reading the same enrichment key from the same payload, so no single game_log value could ever satisfy both — sending dicts would crash the L10 module (caught and downgraded to a data-quality reject), and sending plain numbers would leave the WNBA opportunity gate seeing zero valid games.
Code fix applied in Replit (artifacts/flask-scoring-api/gate_engine/wnba/opportunity_engine.py, plus one call site in app.py's audit endpoint): the WNBA opportunity gate now reads a new dedicated key, box_score_log, instead of reusing game_log. l5_l10_ledger.py and pipeline.py are untouched and still use game_log as plain numbers. I verified the fix compiles cleanly (error count back to the file's original baseline) and traced every call site so nothing else silently breaks.
