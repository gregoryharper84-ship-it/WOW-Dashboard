Replit responsibilities

1. Kalshi API client

Start read-only / paper-trade only.

Kalshi has public market-data endpoints, and its docs say the API supports REST, WebSocket, and FIX for market data and execution.   Public market-data requests can use the production endpoint at external-api.kalshi.com/trade-api/v2, and the quick-start docs say some public endpoints do not require authentication.  

Build:

GET market by ticker
GET event/series
GET orderbook
GET market status
GET trades/candles if available

Do not build live order submission first.

⸻

2. Order book normalizer

This is important because Kalshi’s order book returns YES bids and NO bids, not a normal sportsbook-style line. Kalshi’s docs explain that a YES bid at price X is equivalent to a NO ask at 100 - X.  

Replit should normalize this into:

best_yes_bid
best_yes_ask
best_no_bid
best_no_ask
yes_spread
no_spread
depth_at_price
depth_within_1c
depth_within_2c
mid_price

This becomes the Kalshi version of the sportsbook market screen.

⸻

3. Fee model

Add a fee calculator before any approval.

Required output:

raw_edge
estimated_fee
spread_drag
slippage_drag
uncertainty_tax
adjusted_edge

The Kalshi fee schedule uses a price-based contract formula, so Replit needs this as code, not manual math.   Also account for fee rounding behavior if you later simulate fills at scale.  

⸻

4. Edge engine

Core formula:

raw_edge = model_probability - entry_price_probability
adjusted_edge = (
    raw_edge
    - fee_drag
    - spread_drag
    - slippage_drag
    - uncertainty_tax
)

Hard rules:

adjusted_edge >= 4% for liquid sports/weather
adjusted_edge >= 5-6% for macro/news
adjusted_edge >= 6-8% for thin/narrative markets
otherwise reject
