Mostly **Replit side**.

ChatGPT can format the request, pass board data, and enforce output rules, but the missing fields and scoring gates need to live in the **Replit LLP engine** because that is where the model actually computes:

* starter / lineup confirmation
* opening-line movement
* CLV status
* timing score
* market efficiency
* fragility index
* payout friction
* Kelly %
* final BET / SMALL BET / WATCH / PASS decision

### 2. Pre-Layer-4 gate

Before Layer 4 synthesis, Replit should run:

```text
official confirmation
starter / lineup validation
opening-line lookup
CLV comparison
run environment / scoring context
moneyline fragility index
payout friction layer
Kelly adjustment
```

### 3. Do not promote without confirmation

The Replit model should enforce:

```text
If opening_line missing → no approved bet
If CLV reference missing → cap at WATCH
If starter/lineup unverified → cap at WATCH
If Kelly <= 0 → no BET
If short favorite edge < 4% → no BET
```

### 4. Store postmortem data

Replit should save:

```json
{
  "bet_line": -136,
  "close_line": -154,
  "clv_delta": 18,
  "result": "win/loss/push",
  "closing_implied_probability": 0.606,
  "bet_implied_probability": 0.576,
  "actual_clv_beat": true
}
```

That makes future runs smarter and gives the engine settlement accountability.

## What belongs on ChatGPT side

ChatGPT should only do orchestration and formatting:

* request today’s board
* send team-side rows to Replit
* require required fields in output
* refuse to force picks
* display Candidate / Qualified / Approved / Watchlist / Pass
* call out missing data clearly

ChatGPT should **not** be the place where CLV or Kelly is permanently computed, because it does not persist the historical line database unless Replit stores it.

## Bottom line

**Replit side needs the model patch.**
