Required Edit 2 — Concrete Winsorization Proxy Definition

The Winsorization rule must be deterministic. Remove vague language such as “90th percentile proxy if available.”

Use this versioned definition:

winsor_cap_v1:
For a ledger with N >= 10:

* Sort the full L10 values ascending.
* Use the 9th-highest value as the empirical 90th-percentile anchor.
* Compute median_l10.
* Compute median_cap = 2.0 × median_l10.
* winsor_cap = min(median_cap, empirical_p90_anchor) only when empirical_p90_anchor is above the median.
* If empirical_p90_anchor is below or equal to median, use median_cap.

For a ledger with 5 <= N < 10:

* Do not use empirical percentile.
* Use winsor_cap = 2.0 × median_available.
* Add LOW_SAMPLE_WINSOR flag.
* Approval ceiling is WATCH_ELEVATED unless full L10 is later built.

For N < 5:

* Do not Winsorize for approval scoring.
* Label DATA_BUILD_PRIORITY or WATCH only.
* No MODEL_QUALIFIED_HOLD.
