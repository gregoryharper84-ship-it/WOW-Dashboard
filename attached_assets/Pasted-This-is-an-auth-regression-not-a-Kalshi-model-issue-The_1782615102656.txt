This is an **auth regression**, not a Kalshi/model issue.

The scan route is live, but the Custom GPT is now being blocked before market retrieval:

```text
Invalid API key
```

So the current blocker is:

```text
Custom GPT Action is not sending the correct X-API-Key header
```

## Fix this in GPT Builder

Go to the **existing Action** for:

```text
create-app-gregoryharper84.legacy platform.app
```

Then check:

```text
Configure → Actions → Authentication
```

Set it exactly like this:

```text
Authentication Type: API Key
Auth Type: Custom
Header Name: X-API-Key
API Key: <your legacy platform/WOW API key>
```

Then click:

```text
Save Action
Save GPT
```

Do **not** put the key inside the YAML. The YAML only defines the API shape. The key belongs in the Action auth settings.

## Most likely cause

When you replaced the full YAML, the Action schema saved correctly, but the **authentication setting either reset, was not saved, or is using an old key**.

That is why the request now fails before any rows come back.

## Verify with curl

Run this outside GPT with the exact same key you put in the Action auth field:

```bash
curl -i -X POST https://create-app-gregoryharper84.legacy platform.app/wow/kalshi/scan \
  -H "Content-Type: application/json" \
  -H "X-API-Key: YOUR_REAL_KEY" \
  -d '{"category":"sports","sport":"MLB","date":"2026-06-27","mode":"scan_only","min_adjusted_edge":0.04,"max_markets":15,"include_raw_markets":true,"include_combo_markets":false,"market_type":"single_game"}'
```

Expected:

```text
HTTP 200
```

If curl works but GPT fails, the GPT Action auth is wrong.

If curl also fails, the key in legacy platform Secrets and the key you are using do not match.
