Build a Replit-hosted “WOW Data Hub” backend for my sports betting research engine.

Goal:
Create a read-only data and scoring hub that connects sports odds, PrizePicks-style prop feeds, Kalshi market data, player status/logs, and WOW scoring logic. Do not build auto-betting or auto-trading execution yet. All money actions must remain manual.

Use:

* Node.js + TypeScript
* Express API
* MCP-compatible tool server layer
* SQLite or Postgres for logs/history
* Environment variables for all API keys
* Clean modular file structure

Core modules to build:

1. PrizePicks/data-feed lane

   * Do not scrape PrizePicks directly.
   * Create adapter interfaces for third-party providers such as OpticOdds, SportsGameOdds, PropLine, or The Odds API.
   * Normalize props into one schema:
     player, team, opponent, sport, game_date, prop_type, side, line, platform, payout_context, source, timestamp.

2. Sportsbook odds lane

   * Pull sportsbook markets from provider APIs.
   * Support player props, pitcher Ks, WNBA props, MLB hitter markets, team sides, totals, spreads.
   * Calculate implied probability and no-vig probability.
   * Compare board line vs sportsbook line.

3. Kalshi lane

   * Use official Kalshi API structure.
   * Start with read-only market scans.
   * Support categories: sports, weather, macro, politics, entertainment, news.
   * Do not place orders yet.
   * Return market ticker, title, yes/no prices, spread, liquidity, adjusted edge, and timestamp.

4. Player status/logs lane

   * Create adapters for ESPN and future paid feeds like SportsDataIO/Sportradar.
   * Pull game slate, player status, probable starters, boxscore/gamelog data where available.
   * If data cannot be retrieved, return DATA_UNOBTAINABLE, not fake values.

5. WOW scoring layer
   Implement WOW v16-style gate logic:

   * Source Access Status
   * Calibration Health Gate
   * Board Lock / Candidate Extraction
   * Cross-Market First Gate
   * Role/status verification
   * L5/L10 exact-line ledger or reconstruction
   * Market/projection check
   * Probability component ledger
   * Payout context
   * Failure path matrix
   * Slip exposure/correlation check
   * Terminal bucket assignment

Valid terminal buckets:
FINAL_APPROVED, MONEY_QUALIFIED, MARKET_VERIFIED_HOLD, MODEL_QUALIFIED_HOLD, RESEARCH_INTEREST, SOURCE_CONFLICT, REJECT_NO_EDGE, REJECT_BAD_STRUCTURE, REJECT_DATA_QUALITY, SLATE_PURGE, DUPLICATE_EXPOSURE_BLOCK, NO_PLAY.

Never output bare HOLD, WATCH, PASS, LEAN, CONDITIONAL, or NO BET as final labels.

Approval rules:

* No forced picks.
* NO PLAY is valid.
* No approval from screenshots alone.
* No approval from L5/L10 alone.
* No approval from market drift alone.
* No approval from narrative alone.
* No approval from unsupported model probability.
* FINAL_APPROVED requires live status, current line, payout, L10/reconstruction, market/projection support, positive EV, and clean exposure.
