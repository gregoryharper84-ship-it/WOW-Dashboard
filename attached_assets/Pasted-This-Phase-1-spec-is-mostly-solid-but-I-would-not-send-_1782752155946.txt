This Phase 1 spec is mostly solid, but I would **not send it exactly as written**. I’d make 5 small fixes so ChatGPT/legacy platform doesn’t implement a broken or misleading helper.

### Fix before sending

1. **`_calculate_efficiency_gap(bbref_log)` should accept `line_pitches_per_inn` directly**, not return an inner function. The current closure pattern is awkward and easy to misuse.

2. **Do not call efficiency for strikeouts.** A K line like `7.5` is not “pitches per inning.” Efficiency should only apply to:

   * 1st Inning Pitches
   * Total Pitches
   * maybe outs/IP-derived props later

3. **Use `_pitcher_fs`, not `_pitcher_fantasy_score`**, because your audit says the existing anchor is `_pitcher_fs` around line 6780.

4. **Savant K% approximation is wrong if denominator is total pitches.** Strikeouts / pitches is not K%. Better name it `strikeout_events_per_pitch` or compute true K% only if batters faced can be derived. For Phase 1, keep it as a pressure signal but don’t call it true K%.

5. **FanGraphs team abbreviation matching may fail.** Team rows often use full names, not `CIN`, `PIT`, etc. Add a small alias map or fallback fuzzy match.

FUNCTION 1: _calculate_efficiency_gap(bbref_log, line_pitches_per_inn)
────────────────────────────────────────────────

Purpose:
Detects when a pitch-count or inning-pitch line is set above/below the pitcher's recent per-inning efficiency.

Important:
Do NOT use this for strikeout lines. A K line is not pitches per inning.

Logic:
Use most recent BBRef row:
most_recent_row = bbref_log[-1]

Read:
pitches = row["Pit"] or row["pitches"]
ip = row["IP"]

If missing:
return {
"recent_p_per_inn": None,
"gap": None,
"flag": "EFFICIENCY_DATA_MISSING"
}

ip_float = _ip_to_outs(ip) / 3

If ip_float <= 0:
return {
"recent_p_per_inn": None,
"gap": None,
"flag": "EFFICIENCY_DATA_MISSING"
}

recent_p_per_inn = pitches / ip_float
gap = (float(line_pitches_per_inn) - recent_p_per_inn) / recent_p_per_inn

if gap > 0.15:
flag = "LINE_ABOVE_RECENT_EFFICIENCY"
elif gap < -0.15:
flag = "LINE_BELOW_RECENT_EFFICIENCY"
else:
flag = "EFFICIENCY_ALIGNED"

Returns:
{
"recent_p_per_inn": round(recent_p_per_inn, 2),
"gap": round(gap, 3),
"flag": flag
}

FUNCTION 2: _leash_score(bbref_log)
────────────────────────────────────────────────

Purpose:
Numeric 1–10 leash score from recent start log.
Higher = shorter leash / more pull risk.

Logic:
Use last 5 valid rows of bbref_log.

recent_ip = [_ip_to_outs(row["IP"]) / 3 for row in L5 if IP exists]
avg_ip = mean(recent_ip)

If fewer than 2 valid starts:
return {
"leash_score": None,
"leash_grade": "UNKNOWN",
"avg_ip_l5": None,
"trend": "UNKNOWN",
"flag": "LEASH_DATA_MISSING"
}

Score components:

ip_score:
avg_ip >= 6.0  → 0
avg_ip >= 5.0  → 1
avg_ip >= 4.0  → 2
avg_ip < 4.0   → 3

trend_score:
if recent_ip[-1] < recent_ip[0] - 0.5:
trend_score = 2
trend = "SHORTENING"
elif recent_ip[-1] > recent_ip[0] + 0.5:
trend_score = 0
trend = "LENGTHENING"
else:
trend_score = 1
trend = "STABLE"

consistency_score:
stdev < 0.5 → 0
stdev < 1.0 → 1
stdev >= 1.0 → 2

raw_score = ip_score + trend_score + consistency_score

Convert to 1–10 scale:
leash_score = min(10, max(1, raw_score + 1))

leash_grade:
1–3  → "LONG"
4–6  → "MEDIUM"
7–10 → "SHORT"

Returns:
{
"leash_score": int,
"leash_grade": str,
"avg_ip_l5": round(avg_ip, 2),
"trend": trend
}
