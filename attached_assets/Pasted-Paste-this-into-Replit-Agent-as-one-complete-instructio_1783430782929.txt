## 1. Terminal Bucket Regression Test Suite

Create regression tests proving the scoring engine enforces WOW v16 terminal bucket discipline.

Valid terminal buckets only:

* FINAL_APPROVED
* MONEY_QUALIFIED
* MARKET_VERIFIED_HOLD
* MODEL_QUALIFIED_HOLD
* RESEARCH_INTEREST
* SOURCE_CONFLICT
* REJECT_NO_EDGE
* REJECT_BAD_STRUCTURE
* REJECT_DATA_QUALITY
* SLATE_PURGE
* DUPLICATE_EXPOSURE_BLOCK
* NO_PLAY

Invalid final labels:

* HOLD
* WATCH
* PASS
* LEAN
* CONDITIONAL
* NO BET
* APPROVED unless mapped to FINAL_APPROVED
* TEMP APPROVED
* SAFE
* LOCK

Test cases required:

A. Missing L10
Input prop has market data and status but missing l10_values / l10_median / l10_mean.
Expected: cannot reach MONEY_QUALIFIED or FINAL_APPROVED.
Expected bucket: REJECT_DATA_QUALITY or MODEL_QUALIFIED_HOLD.

B. Missing payout context
Input prop has market, status, and L10 but missing payout_context.
Expected: cannot enter slip.
Expected cap: MODEL_QUALIFIED_HOLD or RESEARCH_INTEREST.

C. Missing status timestamp
Input prop has market and L10 but no status_timestamp / role_timestamp.
Expected: cannot approve.
Expected bucket: REJECT_DATA_QUALITY or MODEL_QUALIFIED_HOLD.

D. Missing market
Input prop has L10 and status but no market comparison.
Expected: max MODEL_QUALIFIED_HOLD unless proprietary module explicitly supports it.
Expected: no MONEY_QUALIFIED or FINAL_APPROVED.

E. Source conflict
Input prop has conflicting market lines or conflicting player status.
Expected terminal bucket: SOURCE_CONFLICT or cap below money labels.
Expected: no MONEY_QUALIFIED or FINAL_APPROVED.

F. Mock/fallback data
Input prop source is mock, fallback, DATA_UNOBTAINABLE, or PROXY_ONLY.
Expected: cannot reach MONEY_QUALIFIED or FINAL_APPROVED.
Expected: RESEARCH_INTEREST, MODEL_QUALIFIED_HOLD, or REJECT_DATA_QUALITY depending on fields.

G. Negative edge
Input prop has complete data but edge_vs_friction <= 0 or final_model_prob <= effective_floor.
Expected bucket: REJECT_NO_EDGE.

H. Bad slip structure
Input slip has 3+ correlated same-script legs without correlation EV math.
Expected terminal slip label: DUPLICATE_EXPOSURE_BLOCK or REJECT_BAD_STRUCTURE.

I. Row count reconciliation
Input board has N props.
Expected output rows = N.
Expected bucket counts sum to N.
If mismatch, return RUN_INVALID / ROW_COUNT_MISMATCH in execution report.

Acceptance:

* Add tests under tests/ or existing test folder.
* Tests must run with pytest or current project test runner.
* Add npm/python script if needed:

  * python -m pytest
  * or npm test if frontend tests exist.
* Do not require real API keys for regression tests.

## 2. Source Status Simulator

Build a dev/test utility that can simulate all source statuses through the scoring pipeline.

Allowed source statuses:

* RETRIEVED
* RECONSTRUCTED
* PROXY_ONLY
* DATA_UNOBTAINABLE
* INPUT_FAILURE
* SOURCE_CONFLICT
* NOT_CALLED
* FAILED

Add a route:
POST /api/dev/source-status-sim

Request body:
{
"source_status": "DATA_UNOBTAINABLE",
"sport": "WNBA",
"prop_type": "points",
"side": "LESS",
"line": 20.5,
"include_market": true,
"include_l10": false,
"include_status": true,
"include_payout": true
}

Response body should include:
{
"input_source_status": "...",
"normalized_prop": {...},
"scored_result": {...},
"terminal_bucket": "...",
"approval_cap": "...",
"blockers": [...],
"can_reach_money_qualified": false,
"can_reach_final_approved": false
}

Rules:

* RETRIEVED + complete clean data may score normally.
* RECONSTRUCTED may score normally only if reconstruction method and source rows are documented.
* PROXY_ONLY cannot approve; max MODEL_QUALIFIED_HOLD or RESEARCH_INTEREST.
* DATA_UNOBTAINABLE cannot approve; usually REJECT_DATA_QUALITY.
* INPUT_FAILURE means raw data was present but scoring did not run; terminal INPUT_FAILURE internally or map to REJECT_DATA_QUALITY if dashboard requires v16 bucket only.
* SOURCE_CONFLICT blocks money labels.
* NOT_CALLED is not the same as unavailable; cap below money labels.
* FAILED blocks approval.

Acceptance:

* Add UI panel or dev-only button if easy, but route is enough.
* Add tests covering all source statuses.
* Do not expose this route as production betting guidance. Label it DEV ONLY.
