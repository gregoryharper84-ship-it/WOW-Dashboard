That sequence is mostly right, but I’d tighten one important point:

**Kalshi does not appear to use a simple single `KALSHI_API_KEY` bearer-token style for authenticated requests.** Kalshi docs say authenticated requests require signed headers using a **Key ID**, **timestamp**, and **signature generated from the private key**. ([Kalshi API Documentation][1])

Also, **public market-data endpoints like markets/order book can be accessed without authentication** according to Kalshi’s quick-start market-data docs. ([Kalshi API Documentation][2]) So if your legacy platform endpoint is returning `KALSHI_DATA_UNOBTAINABLE until KALSHI_API_KEY is wired`, that is probably a **legacy platform implementation choice**, not strictly a Kalshi requirement for public market scans.

## What I would do next

In legacy platform Secrets, add these instead of only one generic key:

```text
KALSHI_ENV=prod
KALSHI_BASE_URL=https://external-api.kalshi.com/trade-api/v2
KALSHI_API_KEY_ID=<your Kalshi API key ID>
KALSHI_PRIVATE_KEY=<your downloaded private key contents or mounted private key path>
KALSHI_DRY_RUN_ONLY=true
ALLOW_LIVE_TRADING=false
ALLOW_MARKET_ORDERS=false
```

Do **not** paste the private key into ChatGPT or the Custom GPT instructions. Put it only in legacy platform Secrets.
