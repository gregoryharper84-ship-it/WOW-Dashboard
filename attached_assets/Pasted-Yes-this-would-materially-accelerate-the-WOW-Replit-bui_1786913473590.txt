### `replit.md` — short, always-on rules

This should contain only universal project rules:

* Replit is the backend/service layer, not the WOW Betting Engine identity.
* `can_execute=false`.
* No wagering, trading, routing, modification, or cancellation.
* Preserve native WOW terminal labels.
* Missing evidence fails closed.
* No downstream gate may erase an upstream blocker.
* No secrets in code, prompts, logs, tests, or documentation.
* No unrelated refactors.
* Every change requires tests, diff evidence, and exact changed-file reporting.
* Database changes require an explicit migration and rollback strategy.
* Production publication requires readiness, regression, and post-publish smoke verification.

Replit automatically uses root-level `replit.md` for project architecture and coding conventions, so it is appropriate for these truly universal rules. [Replit `replit.md`](https://docs.replit.com/features/project-setup/replit-dot-md)

### `wow-replit-patch-governor` — the main development skill

Use one focused engineering skill that forces this sequence:

1. Inspect current code and tests.
2. Produce a bounded implementation contract.
3. Identify allowed and protected files.
4. Record API/schema/runtime effects.
5. Create a checkpoint.
6. Implement the smallest complete change.
7. Run targeted tests.
8. Run mandatory regression tests.
9. Audit the diff boundary.
10. Report raw evidence.
11. Commit independently.
12. Publish only when the task expressly includes publication.
13. Verify production using fresh session/run IDs.

This skill should govern **how Replit modifies WOW**. It should not contain probability formulas, sport logic, or candidate-selection rules.

This is the piece most likely to solve the multi-day build problem. Instead of “finish Universal Agent Core,” Replit receives isolated packets such as:

* UAC-B4.1: schema and contracts only
* UAC-B4.2: service implementation
* UAC-B4.3: route wiring
* UAC-B4.4: ceiling propagation
* UAC-B4.5: regression and production verification

Each packet ends with an independently reviewable commit.

## Checkpoint warning

Use both Replit checkpoints and Git commits. Checkpoints are excellent for Agent recovery, while Git commits are better for durable, isolated change history. Also, Replit production database restoration is separate from ordinary code rollback, so database migrations need their own recovery plan. [Version control](https://docs.replit.com/learn/projects-and-artifacts/version-control), [development and production databases](https://docs.replit.com/features/data-and-storage/development-and-production)

My recommendation is to add this as an isolated, governance-only patch before the next feature packet:

```text
WOW-PATCH-2026-08-16-REPLIT-ENGINEERING-CONTROL-PLANE-V1
```

It should introduce instructions, build contracts, verification scripts, and diff controls without changing model probabilities, endpoints, schemas, terminal decisions, or production behavior.
