### Remaining failures

1. **Row reconciliation is incorrect.**
   Clean Core requires:

   ```text
   rows_in = rows_completed + rows_held + rows_rejected
   ```

   The implementation uses `>=` and permits “other,” conditional, and unlabeled rows. Every row must terminate exactly once; `rows_other` must equal zero.

2. **Provenance failure is not fail-closed.**
   A best-effort downgrade on a separate connection can fail while leaving `FINAL_APPROVED` stored. Logging a warning does not satisfy the invariant. The downgrade must occur transactionally, or the final label must be capped before the primary write.

3. **Legacy `FINAL_APPROVED` counting remains unresolved.**
   Rows created before the new enforcement cannot be assumed “genuinely approved.” They are less trustworthy, not more. Unregraded legacy rows must be excluded from canonical approval counts or reported separately as `legacy_unverified_final_approved`.

4. **The actual Kalshi rejection behavior is still untested.**
   The only test calling the validator is skipped. Runtime inspection of frozensets is useful but does not prove that an attempted forbidden label is rejected by the pipeline.

5. **Probability-ledger enforcement only mentions `FINAL_APPROVED`.**
   An incomplete ledger must also cap `MONEY_QUALIFIED` or any equivalent money/final label.

6. **Unknown models apparently pass through.**
   `NO_REGISTERED_MODEL` must independently cap the row unless another tested upstream gate already does so. Missing model coverage cannot pass without restriction.

7. **Global enforcement status is overstated.**
   While items 1–6 remain, `backend_global_ceiling_enforcement_status` cannot truthfully report every component as `ACTIVE_FAIL_CLOSED`.

8. **No production smoke evidence was provided.**
   The report lacks the requested fresh multi-worker governance-prewarm, quota-consistency, and endpoint reconciliation results.
