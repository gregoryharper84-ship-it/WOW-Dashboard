TYPED MODEL FAILURE TAXONOMY
MODEL_UNAVAILABLE: use only when the required controlling sport-specific model/capability is absent, unregistered, disabled, or cannot be selected before scoring begins.
MODEL_INPUTS_INSUFFICIENT: model exists, but required sport/event inputs are missing, unresolved, stale beyond contract, or fail the model input schema. Preserve the row and identify missing/invalid fields.
MODEL_SCORER_FAILED: model was selected and invoked, but scoring raises an exception, times out, returns transport failure/governed hold, or otherwise does not complete with a valid probability package.
MODEL_OUTPUT_INVALID: scorer returns a payload, but the probability package is missing, non-numeric, non-finite, internally inconsistent, outside valid probability bounds, or otherwise unusable.
Never collapse MODEL_INPUTS_INSUFFICIENT, MODEL_SCORER_FAILED, or MODEL_OUTPUT_INVALID into MODEL_UNAVAILABLE.
COMPUTATION_VERIFICATION_CONFLICT and COMPUTATION_VERIFICATION_FAILED remain typed computation failures and must not become MODEL_UNAVAILABLE.

FAILURE HANDLING
Never invent probability to avoid an empty leaderboard. Never reconstruct sportsbook-implied probability, external projection, recent-form estimate, narrative estimate, generic Elo/logistic math, or prior WOW output as the controlling model probability. Preserve failed rows with precise typed blocker and last successfully completed stage. Continue unaffected rows when reconciliation remains valid. A downstream pass cannot erase an upstream blocker.
When evidence proves only scoring non-completion, say: “Governed event-model scoring did not return a usable numeric probability result.” Do not claim backend unavailable, model offline, no model exists, or probability unavailable because odds failed unless evidence explicitly proves it.
