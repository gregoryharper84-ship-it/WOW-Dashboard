## Mission

Use JS Style Intelligence to find structurally attractive props, then use the exact
V17 fitted specialist, calibration, lower bound, failure-path evidence, and current
board state to decide whether the JS thesis survives governed scrutiny.

The purpose is not to copy JS. The purpose is to preserve JS's useful search logic
while allowing the governed models to reject weak JS ideas, prefer cleaner stat
expressions, and elevate stronger non-JS candidates.

## Core pipeline

current board / discovery
-> JS Style structural annotation
-> exact controlling specialist
-> calibrated probability package
-> calibrated lower bound
-> role/opportunity freshness review
-> failure-path / scenario stress review
-> exact-line current-board refresh when required
-> JS + Model Convergence Gate
-> ordinary V17 ranking and portfolio construction
-> V17_TERMINAL_REDUCER

JS_STYLE_SIGNAL != GOVERNED_MODEL_PROBABILITY

## Convergence states

### JS_MODEL_STRONG_CONFIRMATION
Use only when:
- JS candidate=true;
- governed model package is publishable and rank eligible;
- numeric calibrated package is valid;
- route/model confidence tier is HIGH;
- role/opportunity evidence is explicitly fresh;
- failure-path/scenario stress explicitly passes;
- exact current line+direction is verified when current PrizePicks publication requires it;
- no material contradiction exists.

This is a selection/construction classification, not a new probability.

### JS_MODEL_CONFIRMED
Use when:
- JS candidate=true; and
- the governed model package is publishable/rank eligible and valid; and
- no material contradiction or explicit stale/stress failure exists;
- but the stronger explicit confirmation conditions are not all proven.

### JS_ONLY_MODEL_HOLD
Use when JS finds a structurally attractive candidate but the governed model package,
freshness, stress, or current-board verification is insufficient.

The JS signal cannot rescue the row.

### JS_MODEL_CONTRADICTION
Use when material role/opportunity, failure-path, or directional contradiction evidence
conflicts with the JS thesis. Do not elevate the row based on JS pattern similarity.

### MODEL_CONFIRMED_NON_JS
A row that is not JS-like may still advance when its governed model package qualifies.
Full Model remains broader than JS Style.

### MODEL_PACKAGE_INCOMPLETE
No valid governed package exists. Preserve the underlying typed model/input/transport
failure. Do not rewrite the failure as a JS status in the underlying scorer.

## Ranking

Official prop ranking remains the controlling V17 route's governed ordering:
calibrated lower bound first where required, calibrated probability as the permitted
tie-breaker, or a stricter route-specific rule.

JS research priority is useful for:
- discovery ordering;
- deciding which candidates deserve deeper evidence collection;
- explaining structural asymmetry;
- selecting among already-qualified construction alternatives only when doing so does
  not override the governed ranking/portfolio rules.

It is not a probability.

## Accuracy improvements

The combined strategy should outperform naive JS imitation through five filters:

1. **Structural discovery**
   JS identifies ceiling/floor asymmetry and opportunity burden that conventional
   surface-level prop scans can miss.

2. **Governed probability validation**
   The exact sport/stat specialist determines whether the selected side actually has
   sufficient calibrated support.

3. **Counterfactual failure-path review**
   Test the reasons the JS thesis can fail: role spike, minutes extension, pass-volume
   reversal, overtime, shot-volume reversal, game-script flip, usage redistribution,
   or other sport-specific regimes.

4. **Current-state reconciliation**
   Re-check role/news/status and exact line/direction. A good historical JS thesis is
   not sufficient if the current role or board has changed.

5. **Portfolio improvement**
   Prefer the strongest governed leg and the cleanest expression of the thesis.
   Replace a marginal shared hinge with a superior independently qualified candidate
   when available; otherwise shrink the card.

## Learning loop

Wins and losses both feed the JS learning ledger.

Model improvement uses the governed process:

Discover
-> Hypothesis
-> Challenger
-> Historical Replay
-> Counterexample Review
-> Holdout / Forward Validation
-> Regression
-> Recommendation

Two distinct future models may exist:

- JS selector challenger:
  P(JS selects row | pregame board features)

- sport/stat fitted specialist:
  P(prop wins | certified sporting inputs)

Do not merge those targets without a separately fitted, calibrated, certified
probability artifact.

## User-facing interpretation

When both layers agree, describe the row as:
"JS structure + V17 model confirmed"

When JS likes a row and V17 does not:
"JS-style candidate, model did not confirm"

When V17 likes a row that is not JS-like:
"V17 model-qualified, not dependent on JS style"

Always display the governed probability/lower bound separately from JS research
priority and archetype metadata.
