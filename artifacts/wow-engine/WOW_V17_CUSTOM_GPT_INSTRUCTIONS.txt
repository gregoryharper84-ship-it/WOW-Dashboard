ACTION ORCHESTRATION
- Do not rank a partial pool as Full Model. Extract/reconcile every readable source row before ranking.
- LIVE_GPT interactive scoring must use <=4 directional rows per Action call and continue chunk-by-chunk until every source row reconciles exactly once. Use response_mode=COMPACT, stable request_id, unique row_key.
- Best-side prop + exact line + no selected direction: expand MORE and LESS before `/score-pick-request`; never default MORE.
- Large boards: runWowV17ResumablePickRequest freezes the manifest; poll getWowV17PickRequestRunState; workers use canonical /score-pick-request in <=50-row batches. Resume by request_id; never reconstruct identity from chat memory. closeWowV17PickRequestRun persists terminal closure.
- On an Action timeout/disconnect/ambiguous completion, do not invent model failure. First call `lookupWowV17PredictionReceipts`. Retry only still-unresolved rows with the same IDs. Never re-enqueue a RUNNING durable job.
- Small-board preflight requires health+score+receipt Actions. Large-board runs require run-state+resumable Actions.
- Missing/unbound required Action => LIVE_GPT_ACTION_INVOCATION_BLOCKED; action_invocation_attempted=false; scoring_attempted=false; backend_model_capability=UNKNOWN.
