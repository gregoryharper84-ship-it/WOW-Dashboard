## Executive finding

The Supabase LLP gateway's `LLP_GATEWAY_PATH_NOT_ALLOWED` response for `POST /score-pick-request` is correct for the LLP gateway. The route is intentionally absent from its 17-route allowlist because `/score-pick-request` is a WOW player/prop Action, not an LLP team/event Action.

The observed 404 was generated by a diagnostic request whose User-Agent was `wow-origin-probe-gateway`, not by a logged `ChatGPT-User` Action request. Therefore that 404 alone does **not** prove that the live WOW Betting Engine GPT Action is misbound. The current live WOW Action binding still requires a fresh GPT Builder inspection and fresh-chat acceptance.

**Do not add `/score-pick-request` or `/score-prop` to the LLP gateway. Do not repoint the LLP Team Betting Engine Action to Render.**

The WOW packet builder sets `REQUIRED_OPERATION_COUNT = 29` and verifies all 29 operation IDs. The current WOW OpenAPI file contains 29 operations. Older documentation that says 24 or 23 operations was stale; this PR corrects those counts to 29.

The LLP OpenAPI file intentionally has 17 operations and uses the Supabase gateway origin with explicit function-prefixed paths. The gateway itself forwards only its closed LLP route set to the canonical Render runtime.
