## Census execution defect and recovery (2026-11-04)

A complete macOS clone running Python **3.9.6** passed all 11 initial fixture tests, but the full-history run failed at the 72-hour candidate comparison with `ValueError: Invalid isoformat string: '2026-09-02T10:57:35Z'`. **Mechanism:** `datetime.fromisoformat` on Python 3.9 rejects a UTC `Z` suffix; previous fixtures used only `+00:00`. This predicts a runtime failure when candidate pairs include Git timestamps ending in `Z`, even though a synthetic short-repository fixture passes. The existing grader was changed to normalize ISO timestamps through `parse_time`, and one permanent mixed-`Z`/offset regression fixture was added. **After patch:** the owner fetched the corrected PR branch, ran **12/12 fixture tests successfully**, and then completed the full census with **3,395 commits, 525 merges, 27 tentative rework pairs**. This closes the timestamp execution defect but **does not** prove V28 engineering effectiveness. This is a tooling repair in the same one-shot PR, not evidence that V28 improved production engineering.
